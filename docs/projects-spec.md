# ТЗ: «Проекты» — аккаунты, темы и ответы по проектам

Статус: черновик для согласования · база: `master` @ 218d5d0 (после PR #14 «поиск по теме через аккаунты»).

## 0. Цель и словарь

Оператор ведёт несколько направлений («Крипта», «Фитнес»). **Проект** = набор аккаунтов + своя цель (темы поиска,
свои ссылки, ссылки-ориентиры, фильтры) + свои ответы (ИИ или шаблоны). «Запуск» прогоняет отмеченные проекты
**по очереди**; каждый ищет видео по своим темам и отвечает своими аккаунтами своими текстами.

| Термин | Значение |
|---|---|
| проект | строка `projects`; редактируется во вкладках «Цель» и «Ответы», когда он текущий |
| текущий проект | проект, который сейчас открыт в «Цели»/«Ответах» (`app_settings.ui_project`) |
| в запуске | флаг проекта `enabled`: участвует ли он в «Запуске» |
| участник | связь аккаунт↔проект (`project_accounts`); аккаунт может быть в нескольких проектах |
| свои ссылки | видео, вставленные оператором в проект (`video_pool.source='links'`, `project_id`) |
| ориентир | ссылка, по которой ищутся **похожие** видео и **ключевые слова из названия** |

## 1. Решения оператора (не пересматривать)

1. Аккаунт может состоять в **нескольких** проектах.
2. Несколько тем в проекте: за запуск обходятся **все** темы; «N видео за запуск» — настройка рядом с темами.
3. Проекты запускаются **по очереди**; галочка «в запуске» выбирает, какие.
4. Видео можно брать **повторно** (чёрного списка видео нет); под одним видео могут отвечать **разные проекты**.
5. У каждого проекта **свой** выбор «ИИ / шаблоны» и свои шаблоны.
6. Свежесть и просмотры — **свои** в каждом проекте.
7. Новые аккаунты попадают в «без проекта»; аккаунт **без проекта не работает**.
8. Лимит «ответов в день» — **свой в каждом проекте** (см. §6.3 — как он сочетается с защитными лимитами аккаунта).
9. Прокси — у аккаунта, один и тот же во всех его проектах (как сейчас).
10. Текущие настройки и аккаунты переезжают в проект **«Основной»**, который можно полностью редактировать
    (имя, удаление — как у любого другого, кроме запрета удалить последний проект).
11. Журнал — все проекты сразу, с фильтром по проекту.
12. В проекте одновременно: темы **и** свои ссылки. Свои ссылки также служат **ориентиром**: (а) похожие видео из
    рекомендаций рядом с видео, (в) ключевые слова из названия → поиск как по теме.

## 3. Модель данных (`database.py`)

### 3.1 Таблицы
```sql
CREATE TABLE IF NOT EXISTS projects (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    name              TEXT    NOT NULL UNIQUE COLLATE NOCASE,   -- 1..40 символов, без переводов строк
    enabled           INTEGER NOT NULL DEFAULT 1,               -- «в запуске»
    sort              INTEGER NOT NULL DEFAULT 0,               -- порядок в списке и в очереди запуска
    -- цель
    search_topics     TEXT    NOT NULL DEFAULT '[]',            -- JSON list[str], без дублей (casefold), ≤ 20
    use_similar       INTEGER NOT NULL DEFAULT 0,               -- ориентир (а): похожие видео своих ссылок
    use_title_words   INTEGER NOT NULL DEFAULT 0,               -- ориентир (в): слова из названий своих ссылок
    min_views         INTEGER NOT NULL DEFAULT 0,
    max_views         INTEGER,                                  -- NULL = без верхнего предела
    max_age_hours     INTEGER,                                  -- NULL = любая свежесть
    max_videos        INTEGER NOT NULL DEFAULT 5 CHECK (max_videos BETWEEN 1 AND 50),   -- на тему за запуск
    comments_per_video INTEGER NOT NULL DEFAULT 2 CHECK (comments_per_video BETWEEN 1 AND 100),
    target_mode       TEXT    NOT NULL DEFAULT 'first_reply',
    daily_per_account INTEGER CHECK (daily_per_account IS NULL OR daily_per_account > 0), -- NULL = без своего лимита
    -- ответы
    reply_mode        TEXT    NOT NULL DEFAULT 'ai' CHECK (reply_mode IN ('ai', 'custom')),
    custom_replies    TEXT    NOT NULL DEFAULT '[]',            -- JSON list[str]
    paraphrase_custom INTEGER NOT NULL DEFAULT 0,
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL
);

CREATE TABLE IF NOT EXISTS project_accounts (            -- аккаунт может быть в нескольких проектах
    project_id   INTEGER NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    account_id   INTEGER NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    daily_done   INTEGER NOT NULL DEFAULT 0,             -- ответов в этом проекте за текущие сутки
    daily_reset_at TEXT,                                 -- та же граница суток, что у аккаунта (Database.next_daily_reset)
    added_at     TEXT    NOT NULL,
    PRIMARY KEY (project_id, account_id)
);
CREATE INDEX IF NOT EXISTS idx_project_accounts_account ON project_accounts(account_id);
```
Проверить, что `PRAGMA foreign_keys=ON` включается на каждом соединении (иначе CASCADE не сработает) — если нет,
удалять связи явно в `delete_project` / `delete_account` и покрыть тестом.

### 3.2 Изменения существующих таблиц
- `video_pool`: добавить `project_id INTEGER REFERENCES projects(id) ON DELETE CASCADE`; заменить `UNIQUE(video_url)`
  на `UNIQUE(project_id, video_url)` — одна ссылка может быть в разных проектах. SQLite не умеет менять UNIQUE —
  **пересборка таблицы** (`CREATE video_pool_new … INSERT SELECT … DROP … ALTER RENAME`, индексы заново) в одной
  транзакции, после `_backup_before_migration`. Все `ON CONFLICT(video_url)` → `ON CONFLICT(project_id, video_url)`
  (`add_video_to_pool`, `queue_search_video`). `project_id` после миграции NOT NULL по смыслу (проверка в коде).
- `activity_log`: `project_id INTEGER REFERENCES projects(id) ON DELETE SET NULL`, `account_id INTEGER REFERENCES
  accounts(id) ON DELETE SET NULL`, индекс `(project_id, created_at)`. `ActivityLogCreate` + все три вызова
  `log_activity` в оркестраторе (и в `run_multi_video_pipeline`, если он пишет журнал) передают оба поля. Удалённый
  проект: записи остаются, проект показывается как «удалён».
- `accounts` — **без изменений** (связь в `project_accounts`).

### 3.3 Миграция существующих баз (один раз, идемпотентно)
`Database.init_schema` → `_ensure_projects(conn, cfg_defaults)`; флаг `app_settings.projects_seeded`.
1. Если `projects` пуст и флага нет: создать **«Основной»** из текущего `config.yaml`:
   `search_topics = [collector.search_query]` (если задан), фильтры, `max_videos`, `comments_per_video` =
   `limits.max_iterations_per_session` (так UI считает «ответов на видео»), `target_mode`, `reply_mode`,
   `custom_replies`, `paraphrase_custom`.
2. Все существующие аккаунты → участники «Основного» (иначе по решению 7 у оператора всё перестанет работать).
3. Весь `video_pool` → `project_id = Основной`.
4. Флаг ставится в той же транзакции. Повторный запуск ничего не меняет; удалённый оператором «Основной» не
   пересоздаётся.
Значения из `config.yaml` нужны только для начального заполнения; `init_schema` получает их параметром (база не
должна читать конфиг сама) — продумать, кто передаёт (`AppContext`, `run_*_cli`, оркестратор).

## 4. Конфиг одного проекта для запуска

`modules/projects.py`:
- `project_config(cfg: AppConfig, project: ProjectRecord, topic: str | None) -> AppConfig` — `model_copy(deep=True)`
  с подстановкой `collector.search_query=topic`, фильтров, `max_videos`, `comments_per_video`, `target_mode`,
  `processor.reply_mode/custom_replies/paraphrase_custom`, верхнеуровневых `reply_mode/custom_replies`,
  `limits.max_iterations_per_session`. Глобальное остаётся: ключ/модель DeepSeek, промпты, языки, `limits.*` потоков,
  `account_mode`, браузер, паузы. Проверить, что ни один модуль не перечитывает `config.yaml` с диска в обход
  переданного `cfg` (grep `load_config(` внутри оркестратора/процессора/раннера) — иначе настройки проекта потеряются.
- `project_plan(project, pool_count) -> list[Step]` — что запуск сделает для проекта: темы, ориентиры, свои ссылки;
  пустой план = «нечего запускать» с причиной. Заменяет `_target_plan` для проектов.

## 5. Ориентиры (ссылки → новые видео)

`YouTubeCollector`:
- `related_videos(video_id, limit)` — рекомендации рядом с видео: InnerTube `next` (`/youtubei/v1/next`,
  `secondaryResults` → `compactVideoRenderer`/`lockupViewModel`), через прокси поиска, с теми же разбором просмотров
  и возраста, что `search_videos`, затем фильтры проекта.
- `title_keywords(title) -> str` — запрос из названия: убрать эмодзи, хэштеги, `|`/`[]`/скобки, стоп-слова ru/en,
  числа-мусор; оставить 3–6 значимых слов; пустой результат — пропуск. Чистая функция, покрыть тестами (рус/англ,
  только эмодзи, очень длинное).
- Источник для обоих — **свои ссылки проекта** (`source='links'`), не более K = 5 ссылок за запуск (самые свежие
  добавленные), чтобы не раздувать запросы. Найденное — `queue_search_video(project_id, …)` (source 'search').
- Исключить из результатов сами ссылки-ориентиры и дубли между темами/ориентирами внутри запуска.

## 6. Запуск

### 6.1 Порядок
`run_projects(config_path, dry_run, project_ids=None)` в `youtube_bot.py`:
1. Проекты с `enabled=1` (или явно переданные), в порядке `sort`; без участников-аккаунтов → пропуск с причиной.
2. Для каждого проекта: собрать видео — по каждой теме `search_videos(limit=max_videos)`, затем ориентиры, затем
   незавершённые свои ссылки; всё в пул проекта; дедуп по `video_id` внутри запуска.
3. Один `MultiAccountOrchestrator` на проект (или переиспользуемый с `project_id` — решить по стоимости браузеров;
   браузеры аккаунтов, общих для нескольких проектов, по возможности не перезапускать: держать кэш раннеров между
   проектами одного запуска или явно закрывать — не оставлять висящих процессов Camoufox).
4. Итог: по каждому проекту `найдено / ответов / пропущено (почему)`; общий `Notice` — кратко, подробности в журнале.
5. Ctrl+C / ошибка в проекте: текущий проект корректно закрывается (`close()`), следующие **не** запускаются,
   итог говорит, на каком проекте остановились. Ошибка одного проекта не должна оставлять `video_pool` в
   `in_progress` навсегда — проверить существующий механизм и покрыть тестом.

### 6.2 Оркестратор
- Принимает `project: ProjectRecord | None`. С проектом: аккаунты = `list_project_accounts(project.id, active)`,
  видео = пул проекта, конфиг = `project_config`. Без проекта — нынешнее поведение (CLI `--account`, тесты).
- `activity_log` получает `project_id`, `account_id`.
- `_claimed` и `reserve_payload` — повторы по **комментарию** остаются глобальными: один комментарий получает один
  ответ от всего бота, даже если его нашли два проекта (иначе это выглядит как ферма). Под одним **видео** разные
  проекты отвечать могут (решение 4) — на разные комментарии.

### 6.3 Лимиты (важно для безопасности аккаунтов)
- Защитные лимиты аккаунта (этап, суточный лимит этапа, интервал между комментариями, предохранитель) остаются
  **на аккаунт** и общие для всех проектов: YouTube видит один аккаунт, а не проекты. Их не делить и не умножать.
- Решение 8 («свой лимит в каждом проекте») реализуется как дополнительный потолок проекта `daily_per_account`:
  «не больше N ответов в день с одного аккаунта **в этом проекте**» (`project_accounts.daily_done`). Аккаунт отвечает,
  только если пропускают **оба**: потолок проекта и защитный лимит аккаунта. Режим аккаунта «без ограничений»
  снимает только защитный лимит, потолок проекта остаётся.
- В подсказке/Пробеле аккаунта в проекте показывать оба: «в проекте 2/5 · всего за день 3/8».

### 6.4 «Запуск» (UI)
- Строка на проект: `▸ 📁 Крипта   ▶ в запуске   👥 4  🔍 2  🔗 8   ✅ 12` (←→ в запуске / пропуск), Пробел —
  план («темы: …; ориентиры: похожие, слова; свои ссылки: 8 ждут; лимит 5/акк. в день»), Enter — «запустить
  только этот» (Run) / «открыть в «Цели»» (сделать текущим + GoTab).
- Верхняя кнопка старта — все отмеченные по очереди; боевой — `Confirm`: «🚀 Публикуем: 2 проекта, до 7 акк.?».
- «Чтобы начать» и статус справа — по отмеченным проектам: «Фитнес: нет аккаунтов», «Крипта: нет шаблонов»,
  «нет проектов в запуске». Пока проект один — строки проектов **не показывать**, экран как сейчас.
- Журнал: фильтр «проект ←→» (все / каждый), в строке — имя проекта и аккаунта; запись (`record_view`) — проект,
  аккаунт. Сводка «сегодня» — общая; Пробел на ней — по проектам.

## 7. Интерфейс

Общие правила шелла: значок + коротко, подсказка внизу, Пробел — подробности, Enter — действия, ←→ — значение,
X — отметить несколько, без дублей. **Пока проект один — интерфейс выглядит как сейчас** (строка проекта в «Цели»/
«Ответах» скрыта, в «Аккаунтах» нет группировки), но вкладка «Проекты» есть.

### 7.1 Вкладка «📁 Проекты» (между «Прокси» и «Цель»; клавиши 1–6)
```
 ▸ 📁 Крипта      ▶   👥 4   🔍 2 темы   🔗 8   ✨ ИИ        ✅ 12
   📁 Фитнес      ▶   👥 3   🔍 1 тема   🔗 0   📝 5 шабл.   ✅ 3
   📁 Основной    ‖   👥 0   🔍 —        🔗 0   ✨ ИИ        ✅ 0
   ＋ новый проект
```
- Строка без аккаунтов/без цели/без шаблонов при «шаблонах» — жёлтая, подсказка что сделать.
- Пробел: темы, ориентиры, фильтры, участники (до 5 имён «и ещё N»), лимит на аккаунт.
- Enter — меню: `🎯 цель и ответы` (сделать текущим → «Цель»), `👥 аккаунты N` (экран участников: список всех
  аккаунтов с ▣/▢, Пробел/Enter — включить/исключить, X — массово), `▶ в запуске ←→`, `🔢 лимит в день на акк. ←→`
  (нет/1/2/3/5/10/своё), `⇅ выше/ниже` (порядок очереди), `🔤 переименовать` (Field, проверка уникальности),
  `🧬 копия` (дублирует настройки без аккаунтов и ссылок), `🧹 удалить` (Confirm с последствиями: «3 акк. выйдут из
  проекта, 8 ссылок удалятся, журнал останется»; последний проект удалить нельзя — Notice).
- `+` — новый проект: Field «название», затем сразу текущий и переход в «Цель».

### 7.2 «Цель» и «Ответы»
- Первая строка (если проектов > 1): `▸ 📁 Крипта   ‹ 1/3 ›` — ←→ переключает текущий проект, Enter — к «Проектам».
- Все записи этих вкладок пишут **в проект** (`ctx.update_project(...)`), а не в `config.yaml`. Глобальные строки
  «Ответов» (ключ DeepSeek, проверка ключа) остаются глобальными — визуально отделить, подсказка «общее для всех
  проектов».
- «Цель» при поиске: `🔍 темы N · «биткоин…», «эфир…»` → экран тем (как экран шаблонов: Enter — изменить, `+` —
  добавить, D — удалить; дубли и пустые не принимать), `🎬 N видео на тему за запуск`, свежесть, просмотры,
  кому отвечать, ответов на видео; ниже «🔗 свои ссылки» (вставить, показать, очистить — только проекта) и
  `🧭 ориентир: похожие ▣ · слова из названия ▣` (←→/Пробел), неактивно с подсказкой, пока ссылок нет.
- Переключатель «поиск / свои ссылки» заменяется: проект может иметь и то, и другое (решение 12); «Нет видео»
  — когда нет ни тем, ни ссылок, ни ориентиров.
- Предпросмотр комментариев — по первому видео проекта (своя ссылка, иначе первый результат темы).

### 7.3 «Аккаунты»
- Группы по проектам невыбираемыми заголовками (`📁 Крипта · 4`, `📁 без проекта · 1`); аккаунт в нескольких
  проектах показывается **один раз** в группе первого проекта со значком `📁2` и Пробелом «проекты: Крипта, Фитнес».
  Лучше: переключатель вида «по проектам / списком» (←→ на заголовке) — решить по виду в реальном окне.
- Меню аккаунта: `📁 проекты N` → экран со списком проектов ▣/▢.
- Массовое меню (X): `📁 добавить в проект…`, `📁 убрать из проекта…`.
- Новый аккаунт (`+`, импорт файлом, CLI) — **без проекта** (решение 7); после добавления Notice: «Добавлен, без
  проекта — добавьте в проект, чтобы он работал» и строка-подсказка в «Запуске».

### 7.4 Шелл
- Клавиши вкладок из числа вкладок (`"123456"`), `HELP` «1–6». `GoTab` по имени вкладки (`GoTab("Аккаунты")`),
  числа убрать из табов. Значки `project` (📁 / `▣`), `similar` (🧭 / `≈`) в `icons.py` — и в emoji, и в plain.
- Строка вкладок должна помещаться в 80 колонок с 6 вкладками и статусом (проверить ширину; при нехватке — статус
  на вторую строку, это уже умеет `render`).

## 8. CLI (`youtube_bot.py`)
- `--project NAME` — запуск только этого проекта (поиск/ссылки/ориентиры); без него запуск без `--search/--video`
  идёт по всем отмеченным проектам по очереди.
- `--search "тема"` без `--project` — как сейчас (через все активные аккаунты, без проектов) — для совместимости;
  с `--project` — тема только на этот запуск, без записи в проект.
- `--videos-file` + `--project` — ссылки в пул проекта; без `--project` — в «Основной» (если есть), иначе ошибка с
  подсказкой.
- Новые: `--list-projects` (имя, в запуске, аккаунтов, тем, ссылок, режим ответов), `--project-add NAME`,
  `--project-accounts NAME acc1,acc2` (добавить), `--project-remove-account NAME acc`.
- `--list-accounts`, `--history` — столбец проектов.

## 9. Подводные камни (обязательно закрыть)
1. Пересборка `video_pool` на базе оператора: копия до миграции, транзакция, проверка числа строк до/после,
   тест на базе «старой» схемы (сгенерировать DDL текущего master).
2. Двойная запись `reply_mode`/`custom_replies` (верх + `processor`) — в проекте одно место; `project_config`
   заполняет оба.
3. Аккаунт в двух проектах подряд: не открывать браузер заново без нужды; не превышать интервал между
   комментариями (защитный лимит общий — при переходе к следующему проекту аккаунт может ещё «остывать»).
4. `_claimed`/`reserve_payload`: один комментарий — один ответ на весь бот, даже между проектами.
5. Пробный режим не пишет `payloads` — повторный пробный запуск возьмёт те же комментарии; это норма, но в журнале
   пробные записи должны помечаться проектом.
6. Удаление проекта во время запуска — запрет (UI блокирует, пока Run идёт — шелл и так вне меню).
7. Удаление аккаунта — связи `project_accounts` удаляются (CASCADE или явно).
8. Имя проекта: обрезка пробелов, без `\n`, уникально без учёта регистра, ≤ 40, не пустое.
9. Темы: обрезка, без пустых, без дублей (casefold), кириллица без порчи (UTF-8 везде, CLI на Windows).
10. Статус справа и предупреждения вкладок (`warn`) — по отмеченным проектам, не по глобальному конфигу.
11. Чтение базы в UI идёт через read-only `sqlite3` (`ctx.query`) — до миграции схемы старые запросы не должны
    падать: `_ensure_schema` в `run_app` уже есть, расширить.
12. Тесты, завязанные на глобальные `collector.*`/`processor.*` в UI, переписать на проект; старые CLI-тесты не
    ломать.
13. Ни один модуль не должен перечитывать `config.yaml` в обход `project_config`.
14. Документация: `CLAUDE.md`, `AGENTS.md`, `.mex/AGENTS.md`, `.mex/ROUTER.md`, `.mex/context/*` — «шесть
    вкладок», проекты, новые ключи CLI.
